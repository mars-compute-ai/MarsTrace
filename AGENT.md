# Agent Instructions

These instructions are for changing the MarsTrace client. An agent that uses the client to
trace a kernel loads the skills in `marstrace/skills/` instead.

## Repository Layout

- `marstrace/`: the `marstrace` command: the job manifest and its translation into a job
  request (`job.py`), cubins and compiler caches (`binary.py`), safetensors files
  (`tensors.py`), the service client (`client.py`) and the shapes of the service's answers
  (`schema.py`), the operations the commands share (`workflow.py`), the stdio MCP server
  (`mcp.py`) and the commands (`cli.py`).
- `marstrace/viewer/`: `marstrace show`, generated by the maintainers' tooling.
- `marstrace/skills/`: the skills users install; the wheel, `.claude-plugin/` and `.mcp.json` package them
  with the MCP server for Claude Code.
- `docs/protocol.md`: the mapping from `marstrace.toml` onto the MarsTrace API.
- `examples/`, `tests/`.

## Conventions

Every change follows the house conventions of github.com/zobinHuang/humanize: the
Python, README and git conventions apply here. Commit messages are one line in
Conventional Commits form, with no agent attribution.

## Project-Specific Constraints

- **The client carries no tracing implementation.** It ships to customers, so it holds no
  instrumentation or scheduling logic, names no internal tool or supplier, and has no text
  that describes how tracing works on the service. Execution stays on the service.
- **Customer-visible text names the product MarsTrace only.** Messages, help, skills,
  docs and `marstrace.json` never name the tracing engine or an earlier name of the
  product.
- **Code reaches the service only through `[workspace]`.** Its `source` and `files` are
  what the user shares with the agent on the GPU host, on purpose; do not add another
  path that carries code to execute.
- **The viewer is generated.** Do not edit `marstrace/viewer/`; the maintainers
  regenerate it, and a hand edit is overwritten.
- **The service contract is the source of truth.** The customer API is section 3 of
  `docs/reference/marstrace.md` in mars-compute-ai/marscompute-maas. A change there
  changes `client.py`, `schema.py`, `job.py`, the fake service in `tests/` and
  `docs/protocol.md` together. The service publishes no JSON Schemas; `schema.py` holds
  the client's own check of every answer.
- **Tests never call the service.** They use the fake service in `tests/fake_service.py`,
  which refuses request bodies with unknown or missing fields, and the fixtures in
  `tests/fixtures/`.

