# Agent Instructions

These instructions are for changing the harness. An agent that uses the harness to trace
a kernel loads the skills in `skills/` instead.

## Repository Layout

- `xtrace_harness/`: the `xtrace` command: the job manifest and bundle (`job.py`), the
  kernel binaries and compiler caches (`binary.py`), safetensors headers (`tensors.py`),
  the platform client (`client.py`), the SASS listing (`listing.py`) and the commands
  (`cli.py`).
- `xtrace_harness/viewer/`: `xtrace show`, generated by the maintainers' tooling.
- `skills/`: the skills users install; `.claude-plugin/` and `.mcp.json` package them
  with the MCP server for Claude Code.
- `docs/protocol.md`: the contract with MarsCompute.
- `examples/`, `tests/`.

## Conventions

Every change follows the house conventions of github.com/zobinHuang/humanize: the
Python, README and git conventions apply here. Commit messages are one line in
Conventional Commits form, with no agent attribution.

## Project-Specific Constraints

- **The harness carries no tracing implementation.** It ships to users, so it holds no
  instrumentation or scheduling logic, names no internal tool, and has no text that
  describes how tracing works on the platform. Execution stays on the platform.
- **No user program runs on the platform.** A job is data: a binary, a launch
  description and buffer contents. Do not add a field that carries code to execute.
- **The viewer is generated.** Do not edit `xtrace_harness/viewer/`; the maintainers
  regenerate it, and a hand edit is overwritten.
- **The protocol changes in step with the platform.** A change to the job specification,
  the endpoints or the result files changes `docs/protocol.md`, the client and the
  platform (mars-compute-ai/marscompute-maas) together; bump the schema tag
  (`xtrace.job/1`) when an old harness could no longer be understood.
- **Tests never call the platform.** They use the fake platform in
  `tests/test_client.py` and the report fixture in `tests/fixtures/`.

## Verification

```bash
pip install -e .
python -m unittest discover -s tests
ruff check .
```

The report fixture is a trace report as the platform returns it. `examples/matmul/matmul.cubin`
is built with the command in its `xtrace.toml`.
